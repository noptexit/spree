# Volume Pricing (Quantity Breaks + Banded Adjustments)

**Status:** Draft — design finalized 2026-09-07, nothing built
**Target:** Spree 6.0 — fully (2026-09-07: first the schema/resolver phases were pulled into the major because `min_quantity` changes the row identity of the released `spree_prices` table; then the whole plan followed — shipping the feature in one release is faster than splitting the UI off by a release boundary)
**Depends on:** Catalog Agreement Rework (6.0-catalog-agreement-rework.md — implemented; owned lists + contextual rules), Price List Automatic Pricing (6.0-price-list-automatic-pricing.md — implemented; the ±% machinery this extends), B2B Quantity Rules (6.0-b2b-quantity-rules.md — the separate ordering axis)
**Author:** Damian + Claude
**Last updated:** 2026-09-07

## Summary

B2B unit prices change with quantity. Today Spree covers the single
threshold elegantly (a price list with a `VolumeRule` — standalone or
catalog-owned — optionally with the ±% adjustment) and stops exactly where
a real ladder begins: a catalog owns one list, so 24/48/96/200 tiers
cannot exist on it, and per-variant breaks cannot exist at all. This plan
closes the gap with two symmetric extensions of the pricing machinery
itself (2026-09-07 review — the earlier promotions-based percent design
was superseded the same day): **fixed contracted ladders become a
dimension of the price row** (`min_quantity` — the shape every platform
with real volume pricing converged on; nobody models tiers as
list-matching rules), and **percentage ladders become quantity bands on
the list's ±% adjustment** — the implemented automatic-pricing machinery
already treats a percentage as *pricing* (computed on read, clean unit
price, never touching explicit rows), so bands are consistent extension
with an already-answered "percent off what": the base price. Both halves
live on the price list and edit on the catalog's Pricing card. Marketing-
visible volume discounts (strikethrough, D2C "buy more save more") remain
promotion territory and are deliberately deferred.

## Key Decisions (do not deviate without discussion)

- **The tier doctrine, one sentence (2026-09-07): promotions = DTC
  consumers, price lists = B2B.** Agreement pricing — fixed or percent —
  lives on price lists and renders as unit prices; consumer-facing
  marketing discounts live on promotions and render as discounts. Every
  volume-pricing question resolves by asking which side of that line it
  sits on.
- **Fixed breaks are price rows, never rules or discounts** (2026-09-07,
  interactive review): `spree_prices.min_quantity` (integer, default 1,
  null: false — integer defaults are house-legal, so every existing row is
  a quantity-1 price with zero backfill); row identity becomes
  `(variant, currency, price_list, min_quantity)` with the unique indexes
  extended accordingly. The resolver picks, within the winning list, the
  row with the **highest `min_quantity` ≤ the line quantity**. Contracted
  unit prices must appear as unit prices on every B2B document — a $9.00
  agreement rendered as "$10.00 minus discount" is unacceptable paperwork.
- **A break ladder beats the list's ±% adjustment for that variant**
  (the market leader's exact precedence, stated in their docs as "volume
  pricing fixes the price"): our resolver already gives
  explicit-row-beats-adjustment; the dashboard marks such variants
  ("fixed tiers — the list's % adjustment doesn't apply here").
- **Breaks live on price lists only in v1** (`min_quantity > 1` requires
  `price_list_id`): base-price tiers would make every D2C PDP
  quantity-dependent — a storefront surface no platform ships natively.
  Lifting it later is deleting one validation; the column is the same.
  **≤10 breaks per variant** (the leader's cap — a UI sanity bound, model-
  validated).
- **Percentage ladders are quantity bands on the adjustment**
  (2026-09-07, superseding the same-day promotions design): the list keeps
  `price_adjustment_percentage` as its quantity-1 value; a new
  `spree_price_adjustment_tiers` table (`price_list_id, min_quantity,
  percentage`, unique per `(list, min_quantity)`) holds the higher bands,
  and the resolver picks the band with the highest `min_quantity ≤ the
  line quantity`, falling back to the column. Computed on read off the
  base price exactly like the implemented adjustment — clean unit prices,
  no discount rows, no promotion machinery — and **never applied to
  explicit rows** (the implemented precedence): a buyer whose price is the
  adjusted base gets "percent off their current price" by construction; a
  buyer with negotiated explicit rows uses fixed breaks. A ladder shared
  across many agreements verbatim is repeated per list — accepted: terms
  differ per agreement, and the genuinely shared case is marketing.
- **Volume pricing stays separate from quantity rules** (MOQ/multiples —
  `6.0-b2b-quantity-rules.md`): ordering constraints and price tiers are
  sibling axes everywhere in the market and in the merchant's own framing
  ("how many they may buy" vs "what they pay"). No coupling, ever.
- **`VolumeRule` on price lists is kept** for list-level eligibility (a
  wholesale list that only exists at 48+) — it swaps whole lists, breaks
  and bands price within one; different jobs, documented as such.
- **Marketing volume discounts stay promotions, later**: a visible
  strikethrough "buy more save more" (D2C) would be a line-quantity
  promotion rule + a quantity-tiered percent calculator (sibling of the
  existing `TieredPercent`) — recorded as the deferred design, not built
  here. Contracted terms never render as discounts; marketing never hides
  as pricing.
- **Quotes/draft orders**: the volume price computes on quantity change
  through the existing repricing path (`quantity` is already in
  `Pricing::Context`); a `price_source: 'manual'` override still beats it
  — the negotiation ordering already recorded.

## Design Details

- Resolution: `find_price_for_list` becomes "rows for (variant, currency)
  on this list, `min_quantity <= context.quantity` (quantity nil → 1),
  pick max `min_quantity`"; nil-amount placeholder rows keep falling
  through per row. Cache keys gain the quantity bucket only where the
  resolution cache is quantity-sensitive (the line-item pricing path
  already carries quantity per call).
- Dashboard: the price-list editor's variant×currency cell shows the
  quantity-1 price with a "+N tiers" badge; clicking opens the inline tier
  editor (`[Min qty | Unit price]` rows, first row locked to 1, add/delete,
  strictly-increasing validation) — one component, reused on the catalog
  page's products-with-prices view. CSV import/export of a list gains a
  `min_quantity` column (one line per tier); the admin price endpoints +
  bulk upsert accept it.
- Storefront: no ladder display in v1 (the merchant's own preference) —
  the line's unit price re-resolves as quantity crosses thresholds. A
  PDP "buy more, save more" widget is a later opt-in read of the same
  rows.
- Banded adjustment: the Pricing card (standalone list page + catalog
  page) gains "Add quantity tier" rows under the existing
  magnitude/direction controls — same tier-editor component as the fixed
  breaks; the resolution cache keys gain the quantity band the same way
  the fixed-break path does.

## Migration Path

1. **Schema** — `min_quantity` on `spree_prices` (default 1) + the
   unique-index reshape; model validations (list-only, cap, increasing
   ladder via uniqueness). In the major so SDK types, CSV shapes, bulk
   upsert and integrations never harden against the old row identity.
2. **Resolver** — quantity-aware row pick + specs (ladder pick,
   placeholder fallthrough, adjustment precedence, owned + standalone
   lists, quantity nil → identical behavior to today until tiers exist).
3. **Banded adjustment** — `spree_price_adjustment_tiers` + resolver band
   pick + specs (band pick, column fallback, explicit-row precedence,
   owned + standalone).
4. **Admin API + dashboard** — tier editor for breaks and bands (both
   homes), CSV, bulk upsert.

No data migration: the integer default makes every existing price a
quantity-1 row.

## Constraints on Current Work

- **Never model a contracted tier — fixed or percent — as a
  discount/promotion**, and never build marketing volume discounts into
  pricing: agreement terms are price rows/bands, marketing is promotions.
- **Price-reading code must pass the line quantity** through
  `Pricing::Context` — a caller that omits it silently gets quantity-1
  prices.
- No coupling between quantity rules (MOQ/multiple) and price tiers.
- Exports/feeds reading list prices must account for tier rows (a
  quantity-1-only export silently drops the ladder).

## Open Questions

None for this scope. Deferred, recorded: base-price (D2C) tiers = one
validation to lift; PDP ladder widget; the marketing volume-discount
promotion pair (`LineQuantity` rule + quantity-tiered percent calculator);
per-tier `kind: percent` on price rows (rejected — bands on the adjustment
cover it with the implemented semantics).
